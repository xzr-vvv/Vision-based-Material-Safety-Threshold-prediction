# A1 视觉先验安全阈值上下界预测 — 实施路径

日期：2026-08-20
定位：A1 = 离线视觉先验模块。输入物体图片 → 输出安全抓力区间 [F_min, F_max]（牛顿）+ 类别（刚体/柔性/易碎）。
依据：Exp-Force 本地数据实测盘点（本文档第四节）+ 既有调研（vision-backbone-survey / rgbd-grasp-force-survey / rgbd-image-datasets）+ [SAFETYVTLA_DATA_REQUIREMENTS_V1.md](../SAFETYVTLA_DATA_REQUIREMENTS_V1.md) 规范。

## 一、基于 Exp-Force 实现 A1：任务定义与数据流

### 1.1 任务形式

```
输入:  单张物体 RGB 图片（腕部相机俯拍，物体占满画面）
输出:  类别 c ∈ {刚体, 柔性, 易碎}
       安全阈值下界 F_min（实测真值语义：刚好不滑落的最小两指总法向力）
       安全阈值上界 F_max（工程推算语义：k × F_min）
```

### 1.2 数据流水线（全部已有资产，路径相对仓库根目录）

```
ExpForce数据集/ExpForce_dataset_官方原始.csv      官方 4 列: 物体名/图片/质量/实测力 F*
        │
        ▼  process_expforce.py（三类规则归类 + k 系数补最大力）
ExpForce数据集/07_ExpForce_安全抓力范围.csv        训练标注表（129 行，含力语义/协议/来源标注）
        │
        ▼  ExpForce单流模型/train_expforce_single.py（当前 ResNet18 多任务头）
expforce_single_stream.pth                        单流权重（不入库，5 分钟重训可复现）
        │
        ▼  ExpForce单流模型/predict_expforce_single.py
prior 输出（类别 + [F_min, F_max]）               A 级交付物：视觉初始力先验
```

### 1.3 力值语义（全链路必须统一，禁止混用）

| 量 | 语义 | 来源 | 性质 |
|---|---|---|---|
| F_min | 两指总夹持法向力，"刚好不滑落"最小值，3 次取中位数，取整 0.25N | Exp-Force 论文实测 | 真值 |
| F_single | = F_min / 2（单指法向力） | 规范默认换算规则 | 换算列，与总力列并存，禁止静默转换 |
| F_max | = k × F_min，k：易碎 2.0 / 柔性 3.0 / 刚体 5.0 | 本仓库工程推算 | **非真值**，禁止当作真实损伤阈值使用 |

### 1.4 当前基线与已知短板

- 验证集准确率 88%；力 MAE：F_min 0.60N / F_max 2.88N
- 易碎类仅 11 个物体，是当前最弱类别
- 跨相机/视角准确率降至 50%（原因排序：视角差 > 物体分布差 > 相机渲染差）→ 落地需目标相机图片微调或复刻采集协议（俯拍/素色背景/物体占满画面）

## 二、Exp-Force 数据盘点：只有 RGB + 安全阈值，无深度 → 单流框架正确；DINOv3 推荐确认

### 2.1 数据内容实测核验（2026-08-20）

**Exp-Force 官方只发布了 4 类资产**（对应 `ExpForce_dataset_官方原始.csv` 的 4 列 + 图片）：

| 资产 | 内容 | 说明 |
|---|---|---|
| 物体名 | 129 个（刚体 61 / 柔性 57 / 易碎 11，本仓库归类） | |
| 质量 | 1g ~ 489g | |
| 实测最小抓取力 F* | 0.25N ~ 7N，两指总法向力语义 | 唯一实测真值力数据 |
| RGB 图片 | 129 张，RealSense D435i 腕部相机俯拍，640×480 统一规格 | **未发布深度图** |

**未发布**：深度图、逐次试验原始值（仅中位数）、逐物体损坏阈值（全球无项目发布）。

**本地一致性核验结果**（脚本实测，见第四节）：
- 129 行标注 × 129 张图片一一配对，0 缺失 / 0 多余
- 全表单位 N；全表力语义 `total_two_finger_normal`
- 类别分布 61/57/11，与 README 声明一致

### 2.2 结论：单流（纯 RGB）是 Exp-Force 的唯一选项

是的——Exp-Force 数据集**只有安全阈值范围（F_min 实测 + F_max 推算）和 RGB 图**，没有任何深度数据。因此：
- 基于 Exp-Force 训练 → 只能走单流（RGB）框架，当前路线正确；
- 双流（RGB + 深度）的深度输入**只能来自自采 RGB-D 相机**（见第三节），Exp-Force 提供不了。

### 2.3 是否推荐 DINOv3？—— 是，单流首选（依据 vision-backbone-survey）

**推荐：DINOv3 冻结骨干 + 轻量分类/力回归头**（Meta AI，2025.08，arXiv:2508.10104，Apache-2.0）：

| 理由 | 说明 |
|---|---|
| 小样本正确范式 | DINOv3 官方最推荐用法就是"冻结骨干 + 线性探测/轻头"，特征无需微调即可用——与本项目 129 张图的小样本场景完全匹配 |
| 性能 | ImageNet-ReaL 90.4%，密集视觉任务全面第一（自监督路线） |
| 型号可选 | ViT-S / ViT-L / ConvNeXt 蒸馏版均有，可按算力选型 |
| 已有工程验证 | dinov3_dual 已实现同范式（冻结 DINOv3 ViT-L + 只训融合头，CPU 可训），backbones/download 脚本可直接复用 |

**注意事项**：
1. 当前 ResNet18 基线是"ImageNet 预训练 + 全网络微调"，DINOv3 方案是"冻结特征 + 轻头"，两者应做对照实验（基线 88% / MAE 0.60/2.88N），小样本上冻结范式预期更稳；
2. DINOv3 权重走 GitHub，下载失败自动回退 DINOv2（`dinov3_dual/download_models.py` 已实现该逻辑）；
3. 跨相机 50% 的短板主因是**视角/相机域差**，靠换骨干解决不了——优先用目标相机图片微调或复刻采集协议，骨干升级是第二优先级；
4. 双流升级的触发条件：自采 RGB-D 数据到位 → 切换 [dinov3_dual](../dinov3_dual/README.md)（DINOv3 ViT-L RGB 流 + Depth Anything V2 深度流，已建好并冒烟测试通过）。

## 三、其他数据集调研：RGB + 深度图 + 安全阈值范围 三要素齐备的 → **不存在**

两轮调研（rgbd-grasp-force-survey、rgbd-image-datasets）的一致结论：**逐物体安全阈值范围标注是全行业空白，没有任何公开数据集同时具备三要素**。行业现状是"两半拼图"：

### 3.1 有 RGB-D 图片、无力值标注

| 数据集 | 规模 | 三类覆盖 | 对本项目用途 |
|---|---|---|---|
| GraspNet-1Billion（CVPR 2020） | 97,280 帧 / 88 物体 | 刚体 ★★★ | 刚体类 RGB-D 图片主力 |
| TransCG（RA-L 2022） | 57,715 帧 / 51 透明物体 | 易碎(玻璃) ★★★ | 易碎类主力；原始深度含空洞 + 真值深度，可训深度质量门控 |
| YCB-Video（RSS 2018） | 133,827 帧 / 21 物体 | 刚体 ★★★ / 柔性 ★ | 柔性半软物（香蕉/海绵）补充 |
| 华盛顿 RGB-D（ICRA 2011） | 25 万帧 / 300 物体 | 刚体 ★★★ / 柔性 ★ | 物体特写视角，与腕部相机形态最接近 |

### 3.2 有力值、无可用 RGB-D 物体图片

| 数据集 | 力值情况 | 缺陷 |
|---|---|---|
| **Exp-Force**（本组数据源） | 129 物体实测最小抓取力真值 | 纯 RGB，无深度图 |
| Hoi!（ETH） | 3048 段 RGB-D + F/T + 夹持力 | 物体是抽屉/门/阀门等**关节机构**，不是被抓取的三类物品 |
| ForceSight（ICRA 2024） | RGB-D + 抓力目标 | 任务场景图（非物体特写）；OneDrive 托管，国内下载不稳 |

### 3.3 结论路线（已商定）

```
RGB-D 图片：GraspNet(刚体) + TransCG(易碎玻璃) + YCB/自采(柔性) + Gen3 腕相机自拍
     +
力值标签：Exp-Force 同类物体标签平移（或按规范自测 3 次取中位数）
     ↓
双流模型 dinov3_dual（DINOv3 + Depth Anything V2，已建好）
```

柔性类 RGB-D 是全行业空白，必须自拍 15~30 个物体补齐；这也是 [数据采集准备/](../数据采集准备/) 物体清单（三类各 60 候选）的用途。

## 四、样本-物体特征统一规范（A1 数据一致性契约）

### 4.1 核心原则

**一行样本 = 一个物体的一次拍摄；所有样本通过 object_id 关联到唯一物体记录；物体级特征（类别/质量/力值/语义）对同一物体的所有图片必须完全一致。**

任何数据集（Exp-Force / 外部 RGB-D / 自采）进入训练前，必须能回答下表每一格：

| 特征 | Exp-Force 现状 | 外部 RGB-D 数据集 | 自采数据要求 |
|---|---|---|---|
| object_id | ✅ E001~E129 | 需重建映射（图片→物体） | objects_模板.csv 的 object_id |
| RGB 图 | ✅ 每物体 1 张 | ✅ 每物体多帧 | 每物体 ≥5 张（A 级最低线） |
| 深度图 | ❌ 无（单流） | ✅ 配对 | RGB-D 相机直出，禁伪深度 |
| 类别 | ✅ 三类已归类 | 需人工映射到三类 | 采集时标注 |
| F_min | ✅ 实测真值 | ❌ 无 → Exp-Force 同类平移 | 3 次独立测量取中位数 |
| F_max | ✅ k×F_min（推算） | 同左 | 同左，标注 data_source |
| 力值单位/语义 | ✅ 全表 N / total_two_finger_normal | 平移时继承 | 必须填 force_total_or_single |
| 质量 | ✅ 官方发布 | 部分（YCB 有） | 实测填写 |

统一 Schema 以 `07_ExpForce_安全抓力范围.csv` 为准（22 列，对齐 SAFETYVTLA_DATA_REQUIREMENTS_V1 的 A 级字段：f_min_value / f_min_unit / f_min_semantics / force_total_or_single / measurement_protocol / trial_count / gripper_model / sensor_model / calibration_id 等）。

### 4.2 2026-08-20 一致性核验结果（脚本实测）

- ✅ 129 样本全部有 RGB 图片且一一配对（CSV 引用 vs 磁盘文件：0 缺失 / 0 多余）
- ✅ 全表力值单位 N（unit 列唯一值）
- ✅ 全表力语义统一 `total_two_finger_normal`（无混入单指语义）
- ✅ 类别分布 刚体 61 / 柔性 57 / 易碎 11，与 README/文档声明一致

### 4.3 发现的不一致问题（待修复）

| 级别 | 问题 | 位置 | 修复 |
|---|---|---|---|
| **P0** | 训练脚本引用旧列名 `min_grasp_force_N`，但 2026-08-19 语义修订后的 CSV 列名为 `f_min_value` → 当前脚本读 07 CSV 会直接 KeyError | [train_expforce_single.py](../ExpForce单流模型/train_expforce_single.py) L72 | 列名改为 `f_min_value`；predict 脚本同查 |
| P1 | 脚本内硬编码 `E:\` Windows 路径（DATA_CSV / IMG_DIR / MODEL_OUT），与本机仓库路径不一致 | train / predict 两个脚本 | 改为相对路径或命令行参数 |
| P1 | 外部 RGB-D 数据集（GraspNet/TransCG/YCB）的图片→物体→力值平移映射表尚未建立 | 待办 | 新建映射 CSV（object_id / 来源数据集 / Exp-Force 参照物体 / 类别） |

### 4.4 切分与禁令（继承规范 A 级）

1. train / test 按**物体**（object_id / family_id）切分，禁止同一物体的不同图片跨集；
2. `max_safe_force_N = k × F_min` 是工程推算值，禁止当作真实损伤阈值上报或训练加权；
3. 总力 / 单指力双列并存，禁止静默转换（`f_min_single_finger_N = f_min_value / 2` 仅作参考列）；
4. 深度数据到位前，不得用单目伪深度冒充 RGB-D 真深度训练双流。
